# Hajimi币与 AI Club 年度预算体系思考

Last updated: 2026-06-03 Asia/Shanghai

作为 AI Club 的负责人，我希望下学期 Hajimi 正式在学校发布后，社团的 AI 资源使用不再是“大家共用一个 key”，也不只是简单给项目发奖，而是形成一套能支持学生创作、老师参与、项目持续迭代的预算和激励体系。

这套体系要解决三个问题。第一，AI Club 成员需要有稳定的基础 token 额度，能正常学习、测试和开发。第二，真正持续创作和迭代项目的学生，应该获得比普通使用者更多的资源和激励。第三，教师 workshop 之后，一部分老师也会加入 AI Club，用 token 做课堂 demo、跨学科项目和学生指导，因此老师使用的预算要单独规划，不能挤占学生的基础额度。

本文按年度 **50,000 元** 的上限预算来规划。这是一个最大容纳方案，不代表必须花满，也不代表每月固定支出 5,000 元。

## 一、预算节奏按校历分为两类月份

参考《万科梅沙书院 2026-2027 学年校历（教职员工版）》，2026-2027 学年可以简单分成 **在校月** 和 **寒暑假月** 两类。

校历中，2026 年 8 月 10 日全体教职工返校，8 月 17 日老生开学注册；2027 年 1 月 4 日第二学期开始；2027 年 2 月 1-20 日为春节假期，2 月 22 日学生返校；2027 年 6 月 18 日学生最后在校，6 月 21 日教师和行政教辅最后在校；2027 年 7 月基本属于暑假。

因此，预算可以按下面方式执行：

| 月份类型 | 对应月份 | 预算建议 |
|---|---|---:|
| 在校月 | 2026.8-2026.12，2027.1，2027.3-2027.6 | 4,000 元/月以内 |
| 寒暑假月 | 2027.2，2027.7 | 1,500 元/月以内 |

这样全年基础执行预算为：

```text
10 个在校月 × 4,000 = 40,000
2 个寒暑假月 × 1,500 = 3,000
年度弹性预算 = 7,000
年度总上限 = 50,000
```

这个结构承认学校节奏的差异：在校月需要支持学生项目、老师 workshop 和项目奖励；寒暑假月主要保留平台维护、少量项目开发和必要的老师/学生支持。年度弹性预算则用于老师 workshop 增加、供应商涨价、临时项目扩容或人数超过预期的情况。

## 二、先把 token 额度、XP 和 Hajimi币分开

Hajimi 里应该同时存在三套口径：token 使用额度、XP 和 Hajimi币。三者不能混在一起，否则后续预算、等级和消费都会变得混乱。

| 口径 | 定位 | 用途 |
|---|---|---|
| token 使用额度 | 真实调用 AI 的预算 | 每人独立 key 或独立额度，每月控制 |
| XP | 经验值 | 等级、贡献记录、活跃度、排行榜 |
| Hajimi币 | 创作激励和站内消费货币 | 打赏、项目奖励、老师悬赏、token 兑换 |

XP 只代表经验和贡献，不应该被消费。Hajimi币才是可以消费和兑换 token 的激励货币。这样用户消费 H币时，不会影响自己的等级和历史贡献。

Hajimi币采用人民币预算记账：

```text
1 H币 = 1 元人民币等值 AI token 预算
```

但 H币不等于现金，也不做自动提现。第一版优先兑换 token，由管理员审核。中转站价格变化时，H币仍然按人民币预算 1:1 记账，实际可兑换到的 token 数量根据当月供应商价格调整。

## 三、年度 50,000 元预算结构

年度预算分成三类：直接 token 使用预算、Hajimi币激励预算、年度弹性预算。

### 1. 直接 token 使用预算

这部分是真实调用 AI 的钱，主要覆盖学生、老师和平台维护。

| 模块 | 年预算 | 说明 |
|---|---:|---|
| 学生个人基础 token 池 | 7,500 | 覆盖 20-30 名学生的基础额度 |
| 学生项目开发追加池 | 8,000 | 支持多项目并行开发 |
| 教师 workshop 与教师 token 池 | 8,000 | 覆盖约 10 名老师的试用、备课和课堂 demo |
| Eric 管理/开发池 | 6,000 | 平台维护、测试、演示和应急开发 |
| 小计 | 29,500 |  |

### 2. Hajimi币激励预算

这部分以 H币形式记录，主要用于创作者、老师项目、精品内容和活动贡献。H币后续可以由创作者申请兑换 token。

| 模块 | 年预算 | 说明 |
|---|---:|---|
| 月度项目奖励池 | 5,000 | 每月前五项目奖励，按 10 个在校月计算 |
| 老师项目立项激励池 | 5,000 | 老师发布立项招聘后的学生悬赏 |
| 内容与活动激励池 | 3,500 | 精品帖、长文、活动贡献、workshop 复盘 |
| 小计 | 13,500 |  |

### 3. 年度弹性预算

最后保留 7,000 元作为年度弹性预算，用于人数增长、中转站涨价、老师 workshop 增加、临时项目扩容等情况。这个池子不是为了增加复杂度，而是为了避免预算太刚性，导致下学期实际使用增长后没有调整空间。

| 类别 | 年预算 |
|---|---:|
| 直接 token 使用预算 | 29,500 |
| Hajimi币激励预算 | 13,500 |
| 年度弹性预算 | 7,000 |
| 合计 | 50,000 |

## 四、在校月如何执行

在校月每月控制在 4,000 元以内。这个额度主要覆盖学生基础使用、项目追加、教师使用、Eric 管理开发、项目榜单和少量内容/活动奖励。

| 模块 | 在校月参考 |
|---|---:|
| 学生基础额度 | 500-750 |
| 学生项目追加额度 | 500-750 |
| 教师 token 使用 | 400-700 |
| Eric 管理/开发 | 500 |
| 月度项目奖励 | 500 H币 |
| 内容、活动、老师立项 | 300-600 |
| 合计 | 2,700-3,800 |

表格里的数字是执行参考，不要求每项都花满。实际执行时，如果某月老师项目少，老师立项和内容活动预算就可以少用；如果学生项目集中开发，则项目追加额度会更高。关键是单个在校月整体不应长期超过 4,000 元，超过部分优先从年度弹性预算中解释和覆盖。

## 五、寒暑假月如何执行

寒暑假月每月控制在 1,500 元以内。2027 年 2 月春节假期占大半个月，2027 年 7 月基本是暑假，这两个月不适合按照正常在校月预算执行。

寒暑假月主要保留三类支出：平台维护、少量仍在推进的项目、必要的老师或学生支持。月榜奖励可以暂停或延后，不需要强行发放。

| 模块 | 寒暑假月参考 |
|---|---:|
| Eric 管理/开发 | 500 |
| 少量学生/老师项目支持 | 500-700 |
| 内容或活动小额奖励 | 0-300 |
| 合计 | 1,000-1,500 |

这样处理后，预算节奏就只剩两档：在校月和寒暑假月，执行上更简单。

## 六、学生 token 额度

学生不应该使用无限共享 key。每个人应该有独立 key 或独立额度，这样才能知道谁用了多少，也能避免免费额度被无意义消耗。

每个 AI Club 成员默认每月有 **25 元基础 token 额度**。这部分是学习、体验模型、prompt 测试、小功能开发和项目调试的基础预算。20 人时每月约 500 元，30 人时每月约 750 元。

如果学生正在开发项目，则按项目数追加预算：

| 开发中项目数量 | 追加额度 |
|---:|---:|
| 1 个 | +25 元/月 |
| 2 个 | +50 元/月 |
| 3 个及以上 | +75 元/月封顶 |

因此单个学生最高可以达到：

```text
25 基础额度 + 75 项目追加额度 = 100 元/月
```

开发中项目的证明方式不需要复杂材料，只通过每周产品迭代会议确认。只要学生在会议中说明进展，展示 demo、设计、功能变化、问题或下一步计划，就可以计入当月开发中项目数量。

## 七、教师 token 额度

教师 workshop 会让老师成为新的 token 使用者。老师的使用不应挤占学生额度，所以单独设置教师 workshop 与教师 token 池。

教师使用可以分三种情况：

| 使用场景 | 额度建议 |
|---|---:|
| 教师 workshop 单次试用 | 20-30 元/人 |
| 加入 AI Club 的活跃老师 | 50 元/月 |
| 准备课堂 demo 或项目课的老师 | 50-100 元/月 |

老师同样应该使用独立 key 或独立额度。workshop 试用额度不长期自动续期；正在带项目或准备课堂应用的老师，可以按月保留额度。按 10 名老师估算，教师预算应优先保障 workshop、课堂 demo 和老师项目准备。

## 八、Hajimi币如何发放

Hajimi币不是签到积分，不应该大量自动发。它有预算意义，所以要主要流向真正产生内容和项目的人。

创作者是 H币的主要激励对象，来源简化为五类：

| 来源 | 奖励 |
|---|---:|
| 项目发布 | 50 H币 |
| 新版本发布 | 20 H币 |
| 用户打赏 | 实际收到 |
| 月榜奖励 | 150 / 125 / 100 / 75 / 50 H币 |
| 老师项目悬赏 | 100 H币 / 立项项目 |

不再细分“第一个完整项目”“优秀维护”“修 bug”等小类。执行上，这些都可以归入项目发布、新版本发布或老师项目悬赏。

普通用户也应该能参与生态，但普通用户不是主要发币对象。普通用户获取 H币的方式应保持少量、可控：

| 来源 | 奖励 |
|---|---:|
| 认证空投 | 3 H币，一次性 |
| 有效项目评价 | 1 H币，每月最多 3 次 |
| 精品帖 / 精品文章 | 10 H币 |
| 月度精选内容 | 30 H币 |
| 活动贡献 | 按活动规则发放 |

这样普通用户可以通过评价、内容和活动参与 Hajimi 生态，也能用 H币打赏项目，但不会让 H币变成大量发放的签到货币。

## 九、Hajimi币如何消费

第一版暂不开发项目解锁功能。现在项目和精品内容数量还不够，如果过早做解锁，会让 Function Hall 的传播和试玩变差。

当前 H币消费方式先保留三种：打赏项目、创作者申请兑换 token、未来参与活动。推荐打赏档位保持简单：

| 档位 | 金额 |
|---|---:|
| 小支持 | 1 H币 |
| 喜欢 | 3 H币 |
| 强烈推荐 | 5 H币 |
| 大力支持 | 10 H币 |

兑换上，第一版优先支持创作者兑换 token，最低兑换门槛建议为 50 H币，由管理员按月审核。月榜奖励和老师项目悬赏可以优先处理。

## 十、月度项目奖励

月度项目奖励应该固定，避免预算过早膨胀。在校月奖励前五项目：

| 名次 | 奖励 |
|---:|---:|
| 第 1 名 | 150 H币 |
| 第 2 名 | 125 H币 |
| 第 3 名 | 100 H币 |
| 第 4 名 | 75 H币 |
| 第 5 名 | 50 H币 |

合计为 **500 H币/月**。

获奖项目必须达到当月 **10+ verified 月活**，项目能正常体验，并且当月在产品迭代会议中有进展。这里的月活建议定义为：当月 verified 用户中，打开、评价、评论或有效使用该项目的独立人数。

这个奖励金额不算过大，但对学生开发者有实际意义。它能覆盖一部分 token 成本，也能让项目榜单和持续迭代产生直接关系。寒暑假月可以暂停月榜奖励，或者把奖励顺延到下一个在校月。

## 十一、老师项目立项招聘

未来 Hajimi 会参考北大未名论坛做模块化板块，其中一个模块可以是“活动与招聘”。老师可以在这个模块里发布项目立项招聘帖、学科项目招募、活动协作帖、研究或工具开发需求。

老师项目奖励来自老师项目立项激励池。规则保持统一：每个老师立项项目默认悬赏 **100 H币**。老师发布立项招聘告示，Eric/admin 审核后发布，学生被选中并正式立项后发放。

这里不做复杂里程碑拆分。项目上线后，就不再依赖老师悬赏追加，而是和其他项目一样，通过月榜奖励和用户打赏获得后续收入。如果一个项目由 2 名学生共同完成，100 H币由老师或管理员指定分配方式。

## 十二、内容与活动激励

内容与活动激励主要支持非项目类贡献，例如精品帖、精品文章、月度精选内容、workshop 复盘、项目体验报告和活动贡献。

这部分第一版不需要做复杂内容积分系统，只需要管理员或老师人工精选后发放 H币即可。这样能控制预算，也能保证奖励和内容质量挂钩。

## 十三、项目解锁功能暂缓

项目解锁功能现在不开发。等 Function Hall 项目数达到 30+、每月活跃项目达到 10+、精品帖或长文累计 50+、月活用户达到 30+、每月打赏流水超过 300 H币后，再考虑开发。

未来可以解锁 AI 额外调用次数、高级关卡、新版本提前体验、作者资源包或老师项目报名优先权。但基础项目体验应尽量保持开放。

## 十四、最终判断

这套体系的重点不是把 50,000 元快速花完，而是建立一个能支撑下学期增长的上限框架。预算执行只分两档：在校月和寒暑假月。在校月控制在 4,000 元以内，寒暑假月控制在 1,500 元以内，剩余 7,000 元作为年度弹性预算。

最终规则可以概括为：

- XP 负责经验和贡献，Hajimi币负责消费和激励。
- 学生有基础 token 额度，开发项目越多，追加额度越高，但每人封顶。
- 老师有独立 token 预算，用于 workshop、课堂 demo 和带学生立项。
- 创作者通过项目发布、新版本、打赏、月榜和老师悬赏获得 H币。
- 普通用户通过评价、精品内容和活动获得少量 H币，并用 H币打赏项目。
- 月榜奖励固定，不随预算扩大立即加码。
- 老师项目悬赏统一化，立项后发放，上线后走榜单和打赏。
- 项目解锁暂缓，等内容和项目规模起来后再开发。
